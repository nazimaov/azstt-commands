# AzSTT Commands

Веб-приложение для сбора, систематизации и проверки аудиозаписей азербайджанской речи —
набор данных для будущей компактной офлайн-модели распознавания голосовых команд
управления музыкой. Сам сборщик данных работает **без какой-либо нейросети**: распознавание
и обучение — отдельный, последующий этап (см. «Дальнейшие шаги» ниже).

Это отдельный проект внутри репозитория `SvenAlice`, никак не связанный с работающим
кодом управления музыкой (`server/`, `desktop/`) — отдельный git-репозиторий, отдельный
стек, отдельный процесс.

## Архитектура

- **Frontend**: React + TypeScript (Vite), мобильная и десктопная вёрстка, запись через
  `MediaRecorder API` прямо в браузере.
- **Backend**: Python + FastAPI, SQLite через SQLAlchemy (с возможностью перехода на
  PostgreSQL — сменой `AZSTT_DATABASE_URL`, без изменений кода).
- Исходные записи (WebM/Opus из браузера) хранятся как есть; отдельно — конвертированная
  копия в WAV PCM mono 16 kHz (через системный `ffmpeg`) для обучения модели. Оригинал
  никогда не перезаписывается.

Подробности структуры — в конце файла.

## Установка на Windows

Нужны: **Python 3.12+**, **Node.js 20+**, **ffmpeg** в PATH (`winget install ffmpeg`),
**git**.

```powershell
cd azstt-commands
.\scripts\install.ps1
```

Скрипт создаёт `.venv`, ставит зависимости backend и frontend, и — если `.env` ещё нет —
создаёт его из `.env.example` со случайным admin-токеном (нужен для входа в `/admin`).

## Запуск

Для разработки (два процесса, с горячей перезагрузкой фронтенда):

```powershell
.\scripts\run_backend.ps1        # в одном окне — http://127.0.0.1:8766
.\scripts\run_frontend_dev.ps1   # в другом — http://127.0.0.1:5173, проксирует /api на backend
```

Для обычного использования (один процесс, backend раздаёт собранный фронтенд):

```powershell
.\scripts\build_frontend.ps1
.\scripts\run_backend.ps1
# открыть http://127.0.0.1:8766
```

Админ-раздел (управление командами/фразами, модерация записей, экспорт датасета) —
`/admin/login`, токен — значение `AZSTT_ADMIN_TOKEN` из `.env`.

## Деплой: GitHub Pages (frontend) + облако (backend)

GitHub Pages отдаёт только статику — backend там работать не может. Поэтому деплой
разделён на два независимых шага.

### 1. Frontend — GitHub Pages (уже настроено)

`.github/workflows/deploy-pages.yml` при каждом пуше в `master`/`main` сам собирает
`frontend/` и публикует на GitHub Pages (Settings → Pages → Source: GitHub Actions).
Адрес backend передаётся при сборке через переменную репозитория `VITE_API_BASE`
(Settings → Secrets and variables → Actions → Variables) — без неё фронтенд открывается,
но все запросы к `/api/...` падают с ошибкой сети, пока переменная не задана.

### 2. Backend — свой хостинг (сделать вручную)

Создание аккаунта на хостинге — то, что должен сделать сам владелец проекта; агент
не создаёт сторонние аккаунты за пользователя. Шаги на примере **Render.com**
(есть бесплатный веб-сервис, проще всего связать с уже запушенным GitHub-репозиторием):

1. Зарегистрироваться на render.com (можно через GitHub).
2. New → Web Service → выбрать репозиторий `azstt-commands`.
3. Root Directory: `backend`. Build Command: `pip install -r requirements.txt`.
   Start Command: `python -m app.main`.
4. Переменные окружения: `AZSTT_ADMIN_TOKEN` (длинная случайная строка),
   `AZSTT_HOST=0.0.0.0`, `AZSTT_CORS_ORIGINS=https://<ваш-аккаунт>.github.io`.
   Порт Render передаёт сам через `PORT` — backend уже учитывает это (`app/config.py`).
5. После деплоя скопировать выданный Render URL (вида `https://azstt-commands.onrender.com`)
   и вписать его в `VITE_API_BASE` (шаг 1) — после следующего пуша/ручного запуска workflow
   фронтенд начнёт обращаться к этому backend.

**Важная оговорка про бесплатный тариф Render (и большинство бесплатных веб-сервисов):**
файловая система там **не постоянная** — при каждом передеплое или обычном
перезапуске (бесплатный план их периодически перезапускает) содержимое `data/`
(SQLite-база и все аудиозаписи) стирается. Это нормально для быстрой проверки, что
всё соединяется и работает, но **не подходит для реального сбора данных** — сохранённые
записи участников будут теряться.

Для настоящего постоянного хранения — один из вариантов:
- платный план Render/Fly.io с постоянным диском (Disk/Volume) — несколько долларов в месяц;
- **Oracle Cloud Free Tier** — по-настоящему бесплатная виртуальная машина с постоянным
  диском навсегда, без автоматического передеплоя, но настройка (своя ОС, HTTPS) сложнее;
- переписать `backend/app/audio/storage.py` на внешнее объектное хранилище (например,
  Supabase Storage/Cloudflare R2 с бесплатным лимитом) вместо локального диска — не
  реализовано в этом MVP.

## Тесты

```powershell
cd backend
.\.venv\Scripts\python.exe -m pytest
```

29 тестов: участники и согласие, загрузка записей (успех/без согласия/повторная отправка/
дублирование/пустой файл/отсутствующая фраза), контроль качества, CRUD команд и фраз с
версионированием, модерация, целостность экспорта.

Фронтенд проверен вручную в браузере (desktop + мобильный viewport): главная → согласие →
запись → пропуск фразы → админка → загрузка аудио → модерация → прослушивание → экспорт
(полный путь, включая реальный HTTP-запрос с файлом, пройден end-to-end).
Автоматических UI-тестов фронтенда в MVP нет — см. ограничения ниже.

## Известные ограничения MVP

- **Нет Alembic-миграций** — таблицы создаются `Base.metadata.create_all()`. Перед первым
  изменением схемы на боевых данных нужно будет добавить миграции.
- **Нет деления датасета на train/val/test по участникам** — экспорт отдаёт плоский список
  записей; разбиение по `participant_id`, чтобы записи одного человека не попадали сразу в
  несколько выборок — следующий шаг (манифест уже содержит `participant_id` в каждой строке).
- **ffmpeg не бандлится**, нужен в PATH отдельно (в отличие от `vlc`/`btaudio.exe` в
  основном проекте — это пилотный инструмент для сбора данных, не конечный продукт).
- **Публичный хостинг возможен (см. раздел «Деплой» выше), но без постоянного хранения
  на бесплатных тарифах** — frontend на GitHub Pages получает HTTPS автоматически, а
  бесплатные веб-сервисы backend (Render и т.п.) стирают диск при каждом передеплое/
  перезапуске. Для реального сбора данных нужен платный диск или отдельная VM
  (Oracle Free Tier) — см. раздел «Деплой».
- **Нет автоматических UI-тестов фронтенда** — только ручная проверка в браузере и полное
  покрытие backend (API, БД, контроль качества, экспорт) автотестами.
- **Неоднозначность "dayan"/"dayandır"** (ТЗ, п.6): `Musiqini dayandır` (пауза) и
  `Dayan`/`Dayandır` (полная остановка) — однокоренные, но разные действия. Зафиксировано
  как есть в `backend/seed_data/initial_commands.yaml` — требует проверки с носителем
  языка перед массовым сбором, код это не решает.
- Один общий admin-токен (как и в основном проекте SvenAlice) — нет multi-admin с разными
  правами; для пилота с одним модератором этого достаточно.

## Дальнейшие шаги (вне MVP)

После накопления достаточного набора одобренных (`approved`) записей — отдельный
эксперимент по обучению компактной модели классификации команд (keyword spotting),
сравнение подходов, оценка не только точности, но и ложных срабатываний на тишине/шуме/
музыке. Это отдельный этап, не часть этого инструмента.

## Структура проекта

```
azstt-commands/
  backend/
    app/
      main.py            — сборка FastAPI-приложения
      config.py           — настройки из .env
      db.py / models.py   — SQLAlchemy: Command, Phrase, PhraseVersion, Participant,
                             Consent, Recording
      schemas.py           — Pydantic-схемы API
      auth.py               — admin Bearer-токен
      seed.py                — идемпотентная загрузка начального набора команд
      routers/public.py       — участники, задания, загрузка записей, статистика
      routers/admin.py         — команды/фразы, модерация, экспорт
      audio/storage.py          — пути и сохранение файлов на диск
      audio/convert.py           — конвертация в WAV 16kHz через ffmpeg
      audio/qc.py                 — автоматические проверки качества
      export.py                    — сборка zip-экспорта датасета
    seed_data/initial_commands.yaml — начальный набор команд (ТЗ п.6)
    tests/                            — pytest (29 тестов)
  frontend/
    src/pages/            — Home, Consent, Record, admin/Login, admin/CommandsAdmin,
                             admin/Moderation
    src/lib/               — recorder.ts (MediaRecorder hook), participant.ts, adminAuth.ts
    src/api/client.ts       — типизированный клиент API
  scripts/                   — install.ps1, run_backend.ps1, run_frontend_dev.ps1,
                                build_frontend.ps1
```
